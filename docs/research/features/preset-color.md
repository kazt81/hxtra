# Preset LED color (`HX_PRESET_COLOR=1`, `tools/features/preset_color.py`, `src/m4/preset_color.s`)

In Preset footswitch mode, each preset's ring and switch icon on the Home screen in its own colour (This Preset, kept in the preset file), lit while selected and dimmed while not; a preset without one lit in Preset LED Color's and off while not selected. Status tags as in [conventions.md](../conventions.md).

- **The stock Preset look** [verified offline]: the LED refresh `0x28dd0b3c` switches on each footswitch's function byte (`tbb` at `0x28dd0b80`); function 13, the one Preset mode gives FS1..FS3, is the case at `0x28dd0c10`. It reads the footswitch's preset (`0x28dd5454(0x28d9607c(), k, &byte)`), the current one (`0x28df0248(0, &cur)`), and turns the ring off when they differ; when they match it sets mode 1 (`0x28db8260(k, 1)`), then the colour `[r10]` (`0x28dd0c3e`, call `0x28dd0c44`): r10 is the literal `0x28dd0f40` = `0x28e3c4a0`, the word `0x0300ff` (the palette's red), and that literal is the word's only use in Entry 0. TogglEXP (function 12) reads the same red for EXP 1 at `0x28dd0c5e` and green `0x28e3c49c` for EXP 2.
- **The Preset-mode Home builder** [verified offline]: `0x28dc712c(home, flag)` (called at `0x28dc8b1a`) writes the three presets of the bank as `bank * 3 + k` and gives icon `home + 0x3f4 + 0x24k` `Icon_SwitchRed` (0x78) for the current preset and `Icon_SwitchDark` (0x112) for the others (`mov.w r1,#0x112; it eq; moveq r1,#0x78` at `0x28dc7194`, setImage at `0x28dc71a0`). [verified on unit, `preset-mode-leds-3`] This builder draws Preset mode's icons: the colours set through its call at `0x28dc71a0` showed. **[hypothesis]** The label builder's function-13 case `0x28dc7288` (controller types 0xe..0x10, Red/RedOff at `0x28dc74ae`) is for a footswitch whose controller selects a preset; it stays stock.
- **Settings**: Preset LED Color, virtual ID `0xe1` (container 113, bits 0..3), label `LED\nPreset` (Preset over LED: "Preset LED" is too long for a line), values Red (default) .. White, Tap LED Color's palette without Rainbow and Random; This Preset, `0xe2` (bits 4..7), label `Preset\nThis`, None (default), Red .. White. `MENU = 'Displays'`: with Tap LED Color in Displays' third slot they open Displays' second page.
- **The colour in the preset file**: key `0x65` (`p.preset_key`, [engine.md](engine.md)), a bin8 of `"HXPC"` and the colour (1 Red .. 10 White), 8 bytes; none for None. `ORDER = 110`, after More snapshots, so it is the file's last key. A load's finder sets This Preset from it, and START sets None, so a preset without the key has none.
- **Another preset's colour** [verified on unit]: the last 8 bytes of its file, read without loading it ([m4/presets.md](../m4/presets.md): directory entry, handle, the store file's size `0x28daa3ec`). The footswitch's preset comes from `0x28dd5454(0x28d9607c(), k, &preset)`, as the LED refresh's Preset case reads it.
- **Hooks**: `own_call` on `0x28dd0c44` (`preset_led`: the current preset's lit colour, This Preset's else Preset LED Color's), `0x28dd0b96` (`preset_off`: the refresh's ring-off call, which its Preset case reaches for a preset that is not the current one; for function 13 a coloured preset gets mode 1 and its dim colour `0x28dd8030(_, i, 0)`, any other call goes on to the stock `0x28db8260`) and `0x28dc71a0` (`preset_icon`: `Icon_SwitchRed` becomes the lit colour's icon; `Icon_SwitchDark` a coloured preset's `Icon_Switch<Colour>Off`, r4 holding the builder's preset at the call). A Home paint `chain_ptr` before-handler (`preset_paint`), when either setting differs from the last applied, re-colours the ring and icon of the footswitch whose preset is the current one, as leaving Global Settings relights no ring and rebuilds no icon. The LED colour setter `0x28db81fc` sends the colour at once to a lit ring, under its own lock.
- **Tests**: `tests/test_preset_color.py` (handlers in unicorn, the stock sites and icons, the build), `tests/test_virtual_settings.py` (a turn on Displays' second page steps it), `tools/hx_devtest.py` case `preset_color` for the unit.
- **On the unit** [verified on unit, 2026-11-16, `preset-mode-leds-3`, .hxf MD5 `e07341aa…`, a RAM run with HX_TAP_COLOR, HX_MORE_SNAPSHOTS, HX_SCREEN_MIRROR, HX_USB_INPUT]: This Preset Green on 006 and Blue on 007, each saved (VIEW + ACTION, Save); Preset mode, bank 006/007/008. 007 selected: FS1 ring dim green `0x000901` with `Icon_SwitchGreenOff`, FS2 lit blue `0xff3200` with `Icon_SwitchBlue`, FS3 off and dark. 006: FS1 lit green, FS2 dim blue `0x0d0400` with `Icon_SwitchBlueOff`. 008 (no colour): FS3 lit red, the other two dimmed. So the Home builder `0x28dc712c` is the one Preset mode uses. The manual test of `preset-mode-leds-4` (#117 at 3eae43b, .hxf MD5 `e66b24c0…`, HX_TAP_COLOR and HX_MORE_SNAPSHOTS, a `--writes pass` run) passed every item: the global colour, This Preset lit and dimmed across a bank, an uncoloured preset in the global colour, an unsaved This Preset forgotten on a reload, Stomp and Snapshot modes as stock, a bank B save and reload; after a power-cycle and a new RAM run the saved colours and bank B were still there. `preset-mode-leds-2` (MD5 `c0e7ba10…`) saved and reloaded This Preset, and showed the first tail read, at `[handle + 0xb4]`, missing the key.
